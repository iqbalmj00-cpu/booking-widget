# Widget build and publishing contract

The widget repository produces a local release. ScaleYourJunk owns integration of
`public/widget/`, commits, provider deployment and live verification. No command in
this repository copies files into the publisher repository.

## Controlled build

Use Node from `.nvmrc` and npm from `packageManager`, then `npm run build`.
The build copies the recorded inputs into a fresh temporary directory, checking
each byte digest while copying. Only `src/`, `public/`, `scripts/`, `package.json`,
`package-lock.json`, `.nvmrc`, `vite.config.ts` and root `tsconfig*.json` files are
staged. Input symlinks are rejected. Helpers must live in those recorded roots.
Use `TMPDIR` on a volume with enough space for a fresh dependency install and cache.

The builder uses the selected Node distribution's bundled npm, checks its version
against `packageManager`, and runs a clean `npm ci --ignore-scripts`. Dependencies
must have integrity hashes and npm-registry HTTPS URLs in the lock; local, linked
and Git dependencies fail. Project `.npmrc`, `npm-shrinkwrap.json`, caller npm
environment variables and caller `npm_execpath` are excluded. Empty task-owned
user/global npm config files, a fresh cache and a bounded environment are supplied;
user credential/config files are neither read nor changed by the builder.

TypeScript receives an explicit staged project path. Vite receives the explicit
staged `vite.config.ts` with native config loading, a bounded workspace root,
`envDir: false` and inline `css.postcss: {plugins: []}`. Alternative Vite files and
all project/ancestor PostCSS files are excluded; PostCSS discovery from a
`package.json` field is disabled too. Ordinary config, TypeScript and CSS/module
reads outside the stage/runtime are denied by Node 24 file permissions, including
absolute helper imports and external TypeScript extends/references. Put intended
PostCSS plugins in the recorded Vite config and lock their dependencies.

Installed dependencies are checked against the lock and dependency graph. After
TypeScript and Vite succeed, staged and original source identities are rechecked,
the manifest and bundle marker are validated, and `dist/` is replaced. Compiler
failures preserve the previous distribution; local checks reject stale source.
Caught publication-rename failures attempt to restore the previous directory. The two-rename
replacement is not crash-atomic and concurrent builds are unsupported. Copying and
before/after checks do not establish an immutable filesystem snapshot.

Node permissions constrain ordinary file reads, not hostile build code. Reviewed
configuration, dependency/native tools and the Node distribution remain trusted;
native addons and child processes are required by Vite and can bypass Node's
permission model. This is not an arbitrary-code sandbox or exhaustive JavaScript
dependency analysis. Lifecycle/release hooks are not run by the controlled builder.

Handoff all three files from `dist/` together:

- `embed.iife.js`
- `embed.css`
- `widget-build-manifest.json`

`loader.js` belongs to the publisher and is not part of this release.
Do not rewrite the manifest, normalize timestamps or transform JavaScript/CSS bytes.
The embedded build identifier is deterministic for the recorded source and toolchain.
`node scripts/source-fingerprint.mjs` only reports current source identity; it cannot
stamp an existing artifact. A direct Vite invocation produces an `unverified-` ID
and no manifest. Use the controlled builder for release candidates.

## Manifest schema version 2

The executable strict validator is `scripts/build-manifest.mjs`. Unknown or missing
fields, incorrect types, unsupported schema versions, nonpositive artifact lengths,
invalid hashes, unsafe/duplicate/unsorted input paths and inconsistent digests fail.
All SHA-256 values are lowercase 64-character hex; commits are full 40-character Git
SHAs; artifact lengths count bytes. The top-level fields are:

| Field | Contract |
| --- | --- |
| `schemaVersion` | Integer `2`; version 1 is rejected |
| `buildId` | SHA-256 of compact `JSON.stringify({source, toolchain})` using the field order generated by `build.mjs`; no clock or timestamp |
| `source.commit` | Widget HEAD observed during the build; not necessarily the source contents of a dirty build |
| `source.workingTreeDirty` | Boolean Git tracked/untracked working-tree status; ignored build output excluded |
| `source.inputsMatchCommit` | Whether every recorded build input, including additions/deletions, matches HEAD |
| `source.files` | Sorted array of `{path, sha256}` for `src/`, `public/` if present, `scripts/`, package/lock, Vite/TypeScript configuration and `.nvmrc`; paths use `/` |
| `source.sha256` | SHA-256 of compact JSON encoding of `source.files` in generated order |
| `source.lockSha256` | Exact `package-lock.json` byte digest, also present in `source.files` |
| `toolchain` | Actual installed `node`, `npm`, `vite`, `typescript`, `reactPlugin`, `react`, `reactDom`, `esbuild`, `rollup` versions; `platform` and `arch` strings |
| `artifacts` | Exactly `embed.iife.js` and `embed.css`, each `{sha256, bytes}` |

The JavaScript must start with exactly one marker:
`/*! SYJ_WIDGET_BUILD_SHA256:<buildId> */` followed by a newline. The reserved
marker prefix must occur only once in the bundle. Validation checks this marker
against the manifest identity, so recomputing a manifest after relabeling Node,
toolchain or source metadata cannot validate unchanged JavaScript. Artifact hashes
include the marker. Local/publisher/live CLI checks also compare the exact lock
digest and Vite, TypeScript, React plugin, React/DOM, esbuild and Rollup versions.
The lock does not independently prove the Node/npm runtime; the controlled builder
records those observed versions. Editing both metadata and artifact bytes is not
cryptographic proof of a real build.

This is reproducibility/provenance metadata, not a cryptographic attestation of a
trusted build machine. Review source and toolchain before accepting it. A dirty
build is explicitly marked; its source commit alone cannot reproduce its bytes.
When frontend history is reconciled or reviewed source is committed, rebuild and
review the resulting new build identity before publishing. Do not relabel the old
artifact with a new source SHA.

## Independent verification boundaries

Run commands from the widget repository. All checks below are read-only.

```sh
# Source fingerprint + complete local manifest/artifact validation.
npm run check:build

# Publisher working copy; does not establish committed or live state.
SYJ_WIDGET_DIR='/absolute/scaleyourjunk/public/widget' npm run check:publisher

# Reviewed publisher commit must exist locally. Supply full immutable SHAs.
node scripts/check-dist-sync.mjs \
  --publisher-repo '/absolute/scaleyourjunk' \
  --publisher-commit PUBLISHER_COMMIT_SHA \
  --expected-widget-commit WIDGET_SOURCE_COMMIT_SHA \
  --expected-build-id REVIEWED_BUILD_ID

# After the publisher has independently verified the provider deployment mapping:
node scripts/check-dist-sync.mjs \
  --publisher-repo '/absolute/scaleyourjunk' \
  --publisher-commit PUBLISHER_COMMIT_SHA \
  --expected-widget-commit WIDGET_SOURCE_COMMIT_SHA \
  --expected-build-id REVIEWED_BUILD_ID \
  --live-base 'https://www.scaleyourjunk.com/widget/'
```

The publisher developer must validate and commit these exact three files together.
Committed comparisons preflight Git object type and size, then read exact binary
`git cat-file blob` output with an explicit adequate buffer. Each release file is
limited to 16 MiB; missing, corrupt, non-blob and oversized objects fail. When using the
GitHub API instead, decode the blob API's base64 content; do not use transformed raw
responses. The manifest's source commit is the widget commit; the publisher commit
is a separate input and must never be substituted for it.

Obtain deployment ID, deployment-to-publisher-commit mapping and aliases directly
from the provider. This script always labels that mapping as separately required.
Live checks require the reviewed committed blobs, HTTPS, status 200, correct MIME,
unchanged final URLs, no redirects, exact asset bytes and the matching manifest.
HTML/login responses fail. Every response must contain exactly one explicit
`charset=utf-8` parameter and valid UTF-8 bytes. Accepted MIME values are
`application/javascript`, `text/javascript` or `application/x-javascript` for JS,
`text/css` for CSS and `application/json` for the manifest. MIME/charset matching
is case insensitive; whitespace and double-quoted `"utf-8"` are accepted. Missing,
duplicate, conflicting, unknown or malformed parameters, other encodings and
invalid UTF-8 bytes fail. HTTP bodies over 16 MiB fail validation after download.
The live JS/CSS headers inspected on September 10, 2026 already specified UTF-8;
the publisher must add the manifest with `application/json; charset=utf-8`.
That header inspection does not verify this candidate's deployment.
Local equality never establishes what a customer received. Roll back only by
releasing a previously reviewed complete asset/manifest set through the publisher's
release process.

## Tests

`npm run test:provenance` covers malformed manifests, missing/stale assets,
source/lock/build/commit mismatches, unsafe paths, fabricated clean provenance,
HTML/login responses, status/MIME/redirect failures and the read-only fingerprint
and release commands, identity relabels/markers, lock/tool versions, charset syntax
and UTF-8 bytes. `npm run test:publisher` exercises actual >1 MiB output, explicit
size limits, corrupt/missing blobs and complete three-file comparisons in isolated
Git fixtures. `npm run test:build-inputs` runs real builds with poisoned Vite,
PostCSS, ancestor/npm configurations and external helpers. `npm run test:build-failure`
checks preservation after a real compiler error. `npm run test:booking` includes durable recovery tests;
`npm run test:rental` verifies pricing and saved receipt terms with mocks.
